# Agent 长期记忆的写入准入

## 一句话

长期记忆的缺陷不是「记错了」，而是**没有准入**——发生过就记住，于是临时结论、推测、被推翻的旧值都会沉淀成后续轮次的前提。正确口径是「写入时就得满足条件」，而不是「先记下来再想办法清理」；对应的判据必须落在**dump 出来的记忆条目**上，不能只看当轮回答。

## 展开

**为什么必须前移到写入侧**：记忆一旦落库，后续每一轮都以它为上下文。事后清理的代价极高——你不知道它不是从哪条记忆推出来的，也很难判断删掉它会不会带走别的推论。写入侧拒绝，成本是一行逻辑；事后纠正，成本是一整轮对话的理解重建。

**四条准入规则**（最小集，缺哪条就对应一类可测缺陷）：

| 规则 | 具体口径 | 缺了它的表现 |
|---|---|---|
| 只写已确认事实 | 用户明确确认的才写；推测与中间态不落库 | 「按月统计」被临时改成「按周」的试探也写进去 |
| 每条带来源 | 消息 id 或工具调用 id + 时间戳，能追溯也能撤回 | 要回溯为什么它记住了错误前提，无从下手 |
| 冲突以最新覆盖 | 旧值保留为历史而非删除 | 改口径后两套前提并存，行为随机 |
| 写入有配额与去重 | 同一结论不反复写入 | 上下文被同义条目挤满，真正重要的被挤出去 |

**用例怎么造**（两条就够定性，不需要几十条）：

1. **前提变更用例**：先说「按月统计」，第三轮改「按周」→ 期望只留「按周」作为生效前提，且旧值可查到是谁、在第几轮改的。
2. **编造落库用例**：让它给出一个工具从未返回过的结论 → 期望不落库；若落库，说明「来源」字段没有被强制。

**判据落在 dump 上，不落在对话上**：跑 10 轮后把记忆条目导出，断言三件事——条目数不超过预期、没有「推测」类标记的条目、每一条都能追到具体来源消息。**只测第一轮回答准确率是测不出这个问题的**，因为错前提的破坏力要到第 3~5 轮才显现，而当轮回答往往看起来完全正常。

**可追溯率做成指标**：有来源的条目 ÷ 总条目。低于阈值即视为缺陷，而不是「记忆质量欠佳」这种无法验收的描述。配套的工程要求是**写入路径强制带来源字段，缺失就拒写**——不是先写进去、事后补一个来源。

**与 RAG 的分工别混**：RAG 管的是**读**——检索召回的片段进上下文；记忆管的是**写**——哪些东西被固化下来。二者都可能造成「带着错前提往下走」，但定位方式完全不同：RAG 看召回片段里有没有错内容，记忆看库里有没有不该存在的条目。判错层会白改一轮 prompt。

**与「完成度判定」是一对**：记忆错误的危害是**前提错**，完成度造假的危害是**结论错**。两者共用同一条纪律——**只认证据，不认模型的声明**；记忆要能追到来源消息，完成度要能追到验收条目的证据。

## 落地到测试动作

- **把 dump 接口列为可测需求**：不能导出记忆条目的系统，这一块属不可测，先在需求侧提出来，而不是测不了就算了。
- **用例设计走「前提变更」而不是「知识问答」**：问它「记住什么了」得到的是模型的自我描述，不是库里的真实内容。
- **回归要跨轮次**：单轮用例集覆盖不到记忆缺陷，必须有一条「多轮 + 中途变更设定 + 末尾核对结论」的长用例。
- **常见误用**：把「它答对了」当成记忆没问题。答案对可能是当轮上下文里就有正确信息，记忆库里那条错的还躺着。
- **常见缺口**：只测写入、不测删除与撤回。用户说「忘掉刚才那条」之后，条目是否真的不可再被检索到，同样要验。
