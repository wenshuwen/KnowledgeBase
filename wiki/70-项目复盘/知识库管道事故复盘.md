# 知识库管道事故复盘

## 背景
面试助手站点接入本地知识库后的一次发布。知识库内容里有大量安全测试示例代码（注入 payload、`<script>`、`<img>` 等），它们以 markdown 代码块/行内代码的形式存在，理应被**转义后**展示为文本。

## 现象
用户报障「访问页面加载遇到问题」。但所有常规检查全部正常：三个静态文件 HTTP 200、字节数与本地一致、md5 相同、JS 语法检查通过、HTML 标签配对无误。

## 排查路径
1. **先复现，不靠猜** —— 无头 Chrome 渲染线上页面，发现 `#fatalFallback` 带 `class="show"`：全屏错误兜底面板盖在页面上，而底下的内容其实渲染成功了
2. **console 抓不到时的手法** —— 本地复制一份插桩版页面，把全局 error 事件的 `type / target / src / msg` 写进 DOM，再 `--dump-dom` 读出
3. 抓到原始报错：
   ```
   type=error | target=IMG | src=https://bank.com/change_password?new_pass=attacker123 | msg=(空)
   ```
   `msg` 为空 + `target=IMG` → 是**资源加载失败**，不是脚本异常
4. 那个 URL 是**CSRF 知识页里的一句示例代码** —— 它被当成真 HTML 渲染，浏览器真的去请求了它

## 根因
前一天的修复引入了反模式：为了不让代码块里的 `[[示例]]` 被误当双链，采用了「**整段替换成 Unicode 占位符 → markdown 转换 → 事后还原**」。两层后果：

1. markdown 拿到的是占位符，**彻底失去对代码内容做转义和 `<code>` 包裹的机会**
2. 事后还原时，把未转义的原始内容直接塞进 HTML —— 示例标签变成真标签

**为什么当时没发现**：这个写法通过了"代码里的假双链被正确忽略"这条针对性测试，却没有验证"代码渲染结果和原来一样"。**修一个问题时只测了那个问题。**

**实际影响远大于报错显示**：14/17 页行内代码失效（正文残留裸反引号）；3 页泄漏可执行 HTML——CSRF 的 `<img>` 会发起真实请求，CRLF 与 XSS 页的 `<script>alert(1)</script>` **会在访客浏览器里真实执行**。缺陷静默存在约一小时，直到一次图片加载失败把它顶出来。

## 修复与验证
- **修法**：换成一次扫描的择一正则（代码分支 ｜ 双链分支），代码分支原样返回、交给 markdown 正常转义，只对非代码分支做双链替换
- **加防**：构建期不变量校验 —— 产物里出现 `<script>/<img>/<iframe>/<form>/<svg>` 等标签即构建失败（退出码 1）。本渲染器不会产出这些标签，出现即是泄漏
- **验证**（真实浏览器前后对比）：兜底面板 弹出→未弹出；示例 HTML 原样注入→`&lt;img&gt;` 转义、原生标签 0 个；裸反引号 14 页→0

## 同一会话连带发现的其他问题

| 问题 | 存活时长 | 暴露方式 |
|---|---|---|
| 筛选栏从未渲染（选择器缺 `#`，错误被 `safe()` 吞掉） | **9 天** | 主动核对容器时发现 |
| 11 条死链（文件名 ≠ 标题，链接按文件名解析） | 1 天 | 孤页/入链统计 |
| 部署推送半新半旧文件（JS 新、CSS 块缺失） | 一次部署 | 部署后字节级核验 |
| 构建不幂等（幂等判据用了带日期的 `version` → **跨天必产生伪 diff**，进而触发无意义提交与重部署） | 1 天（改过，但跨天复发） | 归档时实构建验证 |

可复用的技术沉淀单独成页：[[渲染管道的转义断链]]。

## 沉淀
1. **凡是要绕过解析器的处理，先问一句：还原时内容还会被转义吗？** 不会，就是在制造注入
2. **静默失败比报错更危险** —— 被 try/catch 吞掉 + 不影响主内容 = 永远不会被发现
3. **构建期校验要按不变量设计**（"渲染器不会产出 script 标签"），而不是枚举已知问题类型——不变量能拦住没想过的问题
4. **无头浏览器 + 本地插桩副本**是前端问题的决定性定位手段，比读代码猜快一个量级（环境坑与操作细则见 [[macOS命令行与无头浏览器踩坑]]）
5. **幂等判据里不能出现会变的字段** —— 第一版把判据写成 `version`，而 `version` = 日期 + 内容哈希，跨天必然"不等"，等于没有幂等；改用独立的 `contentHash` 字段才真正生效。与第 3 条同源：**判据要指向不变量，不要指向易变量**

## 如果重来
- 改动渲染管道后，**必须做前后产物 diff**（同输入下新旧实现各跑一遍，比对输出），而不是只测本次要修的那个点
- 全局 error 监听不该用捕获模式兜一切——**资源加载失败不该等同致命错误**，否则一张图 404 就能掩盖真实问题
- 涉及安全示例内容的管道，上线前就应该带着"这些东西绝不能变成真标签"的警惕去设计校验，而不是出了事再补
