# 渲染管道的转义断链

## 一句话
当你为了某个目的把原始文本先替换成占位符、绕过 markdown 解析、事后再还原——**这一步还原时，内容已经离开了转义链路**。示例代码里的 `<img>`、`<script>` 就会变成真标签注入页面，在浏览器里真实执行。

## 场景还原

知识库里有大量安全测试示例，它们以 markdown 代码块/行内代码的形式存在：

````markdown
最严重的 CSRF：`<img src="https://bank.com/change_password?new_pass=attacker123">` 一行就能改密码
````

正常 markdown 渲染下，反引号里的内容会被转义成 `&lt;img ...&gt;` 并包进 `<code>` 标签——**只显示不执行**。

事故的实现是：先把代码片段替换成 `\ue000 0 \ue001` 这种 Unicode 私用区占位符，让 markdown 转换时看不到它们（目的是阻止代码里的 `[[示例]]` 被当成双链），转换后再用正则把占位符**替换回原文**。

```python
# 反模式：占位符替换后还原
masked = CODE_FENCE_RE.sub(placeholder, text)   # 代码 → 占位符
masked = WIKILINK_RE.sub(wl_span, masked)        # 只替双链（看起来对）
html = markdown(masked)                           # markdown 转的是占位符
return unmask(html)                               # ← 这里把原始 HTML 直接塞回去
```

问题出在最后一步：`unmask` 把占位符替换回原始内容时，**markdown 已经没有机会对它做转义了**——它直接成了 HTML 文档的一部分。

## 断链点

```
原文 ──(占位符替换)──> 占位符 ──(markdown 转义)──> 转义后 HTML ──(还原原文)──> ⚠️ 原文未转义注入
                                                    ↑
                                              转义只发生在这一步
                                              还原绕过了它
```

## 修法：一次扫描，代码原样返回

不再分"替换 → 转换 → 还原"三步，改成**一个正则同时匹配代码片段和双链**，用回调决定各自的处理：

```python
WIKILINK_OR_CODE_RE = re.compile(
    r"(?P<code>```...```|`[^`]*`)"          # 代码分支
    r"|\[\[(?P<page>[^\]|]+?)\]\]",           # 双链分支
    re.DOTALL,
)

def _sub(m):
    if m.group("code") is not None:
        return m.group("code")            # 原样返回，交给 markdown 正常转义
    # 只对双链分支做替换
    ...
```

代码片段原样返回 → markdown 见到反引号 → 正常转义内容并包 `<code>` → **转义链路不断**。

## 三个判别要点

1. **凡是绕过解析器的处理，先问：还原时内容还会被转义吗？** 不会，就是在制造注入面
2. **测试不能只测本次要修的那个点**。事故里"代码里的假双链被正确忽略"这条测试通过了，但"代码渲染结果和原来一样"没测——修一个问题引入了另一个
3. **构建期校验要按不变量设计**：本渲染器不会产出 `<script>/<img>` 等标签——出现即是泄漏，退出码 1。不变量能拦住没想过的问题，逐个枚举已知问题类型做不到

## 为什么"按不变量设计"比"枚举已知问题"强

| 思路 | 能拦住什么 | 漏掉什么 |
|---|---|---|
| 枚举已知问题 | 已知的几种泄漏模式 | 没想到的 |
| 不变量（"本渲染器不产出 script 标签"） | **任何**会导致该不变量被破坏的情况，包括没想过的 | 不变量定义之外的问题 |

这个事故里，"占位符还原破坏转义"是第一次想到的问题类型。如果只针对它写检查，下次换个反模式又得再炸一次。改成"渲染器不会产出这些标签"这条不变量，所有破坏转义链路的写法都会被拦住。
