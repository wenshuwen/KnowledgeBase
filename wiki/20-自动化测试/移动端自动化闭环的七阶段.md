# 移动端自动化闭环的七阶段

## 一句话

把「点击 → 跳转 → 返回」串成闭环，真正决定它能不能长期稳定跑的**不是点击动作本身**，
而是每个阶段后面跟着的两行：**校验点**（怎么知道这一步真的成功了）和
**失败处理**（失败了往哪退）。缺任一行，都不算闭环。

## 展开

```text
前置检查 → 冷启动 → 就绪判定 → 单步动作 → 跳转与返回 → 异常分支 → 收尾与证据
             ↑                                                    ↓
             └──────────── 失败时从最近稳定锚点重入 ←──────────────┘
```

| 阶段 | 校验点 | 失败处理 |
|---|---|---|
| 1 前置检查 | 设备在线、App 已安装、账号已登录、网络可达、系统时间已同步 | 任一项不满足即中止告警，**不消耗重试次数** |
| 2 冷启动 | 强杀进程后冷启，确认包名与入口 Activity 正确，记录启动耗时 | 重启设备或清应用缓存后重试一次 |
| 3 就绪判定 | 关键锚点元素出现，**且界面快照连续两次一致**，才开始动作 | 超时即抓截图与 UI 层级树，判为「页面未就绪」 |
| 4 单步动作 | 定位 → 可见可点判定 → 点击/输入 → 结果校验，四步齐全才算成功 | 定位失败先降级到备选定位器，再降级到图像识别 |
| 5 跳转与返回 | 用**页面指纹**（包名 + 关键控件集合）确认到达，返回后再次校验指纹 | 指纹不符判为栈错乱，退回最近稳定锚点重建页面栈 |
| 6 异常分支 | 弹窗、版本升级、登录失效、网络超时、崩溃各有独立处理器 | 识别后关闭或恢复，从最近锚点重入，最多重试 K 次 |
| 7 收尾与证据 | 终态断言 + 业务数据校验，落盘截图、UI 树、日志与关键耗时 | 失败自动重跑一次，用于区分偶发失败与必现缺陷 |

**为什么第 3 阶段要「连续两次一致」**：单次快照一致只是"这一刻长这样"，页面还在渲染时
也会满足。连续两次一致才能排除"正在渲染中"这个最常见的假就绪状态。

**为什么第 5 阶段必须重校指纹**：返回是最容易静默出错的动作——它可能回到的不是你以为的
那一页。不校验就会带着错误的起点继续往下跑，一路绿灯、结果全错。

## 落地到测试动作

支撑这七个阶段稳定重入的，是五条工程约定——**它们比选哪套框架重要得多**：

1. **不写死 `sleep`**：改成「锚点元素出现 **且** 界面快照连续两次一致」才动作。固定等待是假失败的最大来源。
2. **定位优先级固定**：`resource-id` / `accessibilityIdentifier` > 文本 > XPath > 图像/OCR 兜底。每层都要有明确的兜底路径，不能只有一条。
3. **每步都要"到达确认"**：动作后必须有一次页面指纹或业务断言。不确认等于放弃判断权。
4. **返回用系统 back，不盲点坐标**：每次返回后重新校验指纹。坐标点击在分辨率/刘海/字体变化时全线失效。
5. **步骤幂等 + 从最近锚点重入**：重试有上限 K，超限即判定"必现失败"并留存证据，**绝不无限重试**。

### 支撑闭环的依赖条件

| 层面 | Android 路线 | iOS 路线 |
|---|---|---|
| 主机 | 任意系统 + adb（设备内驻留路线不需要） | **必须 macOS + Xcode** 完成首次构建 |
| 设备侧开关 | 开发者选项 + USB 调试；设备内驻留另需无障碍权限 | 开发者模式 + 信任证书 + 关闭自动锁屏（无人值守需去密码） |
| 账号/签名 | 无 | 免费 Apple ID：7 天过期、最多 3 台；付费账号解限 |
| 驱动组件 | 设备端 uiautomator2 服务，或 Appium UiAutomator2 驱动 | [[WebDriverAgent]] 预装到设备 |
| 应用侧配合 | 稳定的 `testID`、可绕过的验证码/风控、干净且可清理的测试数据 | 同左 + 稳定的 `accessibilityIdentifier` |
| 常驻与运维 | 前台服务 + 忽略电池优化；主机侧用 launchd / systemd / 计划任务守护 | 只能靠 WDA 会话守护，会话崩溃后若无去密码则需人工介入 |

**对人的能力要求**：Python 或 JS 熟练；会看 UI 层级树、会写 XPath；懂前台服务与进程守护；
会读日志、会做截图与 UI 树归档；能调图像识别/OCR 的参数。这四项里，「会写点击」是最容易的一环。

### 常见误用

- **用固定 `sleep` 代替就绪判定**：本机跑通、机器一换就全线失败，且失败点看起来毫无规律。
- **只做动作不做断言**：脚本全程绿色，业务结果其实是错的。这类问题的性质与 [[假阴性漏测的六大来源]] 同源。
- **把重试当成万能药**：没有上限的重试会把"必现缺陷"淹成"偶发失败"，最终没人信这份报告。
- **忽略前置检查**：把账号未登录、网络不可达这类环境问题算成脚本失败，污染成功率口径。
