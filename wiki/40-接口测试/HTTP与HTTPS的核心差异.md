# HTTP 与 HTTPS 的核心差异

## 一句话
HTTPS **不是新协议**，而是把 HTTP 跑在 SSL/TLS 之上，补上了四件 HTTP 做不到的事：加密、身份认证、完整性、防重放。

## 差异对照

| 维度 | HTTP | HTTPS |
|---|---|---|
| 安全性 | 明文，可窃听篡改 | 加密，防窃听防篡改 |
| 协议基础 | 直接基于 TCP | HTTP + SSL/TLS |
| 默认端口 | 80 | 443 |
| 证书 | 不需要 | 需要 CA 签发的数字证书 |
| 性能 | 无加解密开销 | 略慢，但 HTTP/2、3 已把差距压得很小 |
| 浏览器标识 | 可能被标"不安全" | 标"安全"，SEO 有加权 |

## HTTPS 补上的四件事

1. **数据加密** —— 机密性，第三方拿不到明文
2. **身份认证** —— 数字证书验证服务器身份，防中间人攻击与钓鱼站
3. **数据完整性** —— 传输中不被篡改
4. **防重放** —— 通过时间戳与随机数机制，防止旧请求被重复使用

实现上用的是**混合加密**：非对称加密负责安全地协商出会话密钥，对称加密负责后续的数据传输（因为对称加密快得多）。

## 测试视角的落点

这几个点最容易在面试里被追问：

- **抓包工具为什么能看 HTTPS？** 因为它在本机装了根证书做中间人——**这恰好说明"客户端信任了根证书就能解密"**，也说明证书校验一旦被跳过，加密就形同虚设。测试时要专门验证 App/客户端**是否校验证书**（不校验证书 = 可被抓包 = 可被中间人）。
- **证书过期、自签名、域名不匹配** 这三种情况的客户端行为要各测一条——很多客户端只报错不中断，属于真实风险。
- **端口与重定向**：HTTP 80 到 HTTPS 443 的跳转是否强制、跳转过程中是否泄漏参数。

## 与其他概念的关系
HTTPS 解决的是**传输层安全**，它**不解决**应用层的身份问题——登录之后服务端怎么认你，是 [[接口鉴权机制-Token与Cookie与Session]] 的事。两者常被混为一谈，面试里区分开是加分项。
