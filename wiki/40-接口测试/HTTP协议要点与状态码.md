# HTTP 协议要点与状态码

## 一句话
HTTP 是**请求-响应模型 + 无状态**的应用层协议。无状态这一条，直接衍生出了后面所有身份认证机制——理解这点，Cookie/Session/Token 的存在就有了解释。

## 四个核心特点

| 特点 | 对测试的意义 |
|---|---|
| **请求-响应模型** | 通信永远由客户端主动发起，服务端被动响应。安全测试里"服务端为什么会主动发请求"就变得可疑（[[SSRF服务端请求伪造测试]] 的立足点） |
| **无状态** | 服务端不记上一次请求。所以必须靠 Cookie / Session / Token 来"记住"身份（见 [[接口鉴权机制-Token与Cookie与Session]]） |
| **支持任意数据格式** | 不限于 HTML，JSON/图片/视频都用同一套协议，断言方式要跟着变 |
| **明文传输** | 传统 HTTP 不加密，内容可被窃听篡改 → 有了 HTTPS（见 [[HTTP与HTTPS的核心差异]]） |

## 版本演进：都在解决同一个问题

| 版本 | 改进 | 解决的是什么 |
|---|---|---|
| HTTP/1.1 | 默认长连接（Keep-Alive） | 省掉每次重连的开销，但同连接内请求仍需排队（队头阻塞） |
| HTTP/2 | 二进制分帧、多路复用、头部压缩 | 同一连接并行发多个请求，互不干扰 |
| HTTP/3 | 基于 UDP 的 QUIC | 彻底解决底层队头阻塞，弱网表现更好 |

**测试视角**：升级到 HTTP/2 或 3 后，**连接复用相关的用例必须重测**——按连接数做的限流、按请求计数做的统计，行为都会变。

## 状态码：分组记忆，别背清单

| 段 | 含义 | 测试关注点 |
|---|---|---|
| **1xx** | 信息性 | `100 Continue`、`101 Switching Protocols`（升级 WebSocket）——接口测试少见，出现往往是协议升级 |
| **2xx** | 成功 | `200` 通用、`201` 已创建、`202` 已接受（**异步任务**，别当成已完成）、`204` 无内容、`206` 范围请求（断点续传） |
| **3xx** | 重定向 | `301` 永久、`302` 临时——**重定向是安全测试的重点**（[[CRLF注入测试]] 可以伪造 `Location` 头） |
| **4xx** | 客户端错误 | `400` 参数错、`401` 未认证、`403` 无权限、`404` 不存在——**401 与 403 的区别是权限用例的判定依据** |
| **5xx** | 服务端错误 | `500` 内部错误、`502` 网关错误、`503` 不可用、`504` 超时——**压测时 5xx 比例是重要指标** |

两个容易混的点：

- **`202 Accepted` ≠ 处理成功**，只表示"收到了"。用例必须再查最终结果，否则会误判为通过。
- **`401` 是"你是谁"的问题，`403` 是"你能不能"的问题。** 越权测试里期望看到 403，如果返回 401 说明鉴权链路有别的毛病。
