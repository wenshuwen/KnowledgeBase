## 测试理论

### 一页纸敏捷测试策略
- 五块内容：范围与不范围 / 分层策略 / 风险与重点 / 准入准出 / 迭代节奏（每日冒烟、提测回归、探索式测试时间窗）。
- 本质是让团队对「质量怎么保障」达成共识的沟通工具；随迭代回顾演进，放团队 Wiki 共享，形式越轻越好。
- 缺陷预防 vs 检测：预防靠需求评审提可测性问题、静态扫描进流水线、给开发提供自测工具集；「让团队少产生 bug」比「找 bug 快」更能体现高级测试的价值。

### 风险驱动测试的优先级矩阵
- 风险 = 失败可能性 × 失败影响。可能性看变更量、历史缺陷密度、新技术引入；影响看资金、用户面、数据安全。
- 四象限投入：高×高全深度 + 自动化；低×高核心路径 + 异常分支；高×低冒烟 + 自动化回归；低×低抽样。
- 最大价值：测试时间被压缩时有据可依地裁剪，而不是拍脑袋砍用例。

## 接口测试

### 下游依赖未就绪的三种应对
1. 挡板虚拟化：按契约（swagger/proto）起 Mock，覆盖正常 + 超时 + 500 + 脏数据四类响应——异常分支反而比真实环境更易覆盖。
2. 契约测试：下游就绪后核对挡板与真实行为一致，防「Mock 过了联调挂了」。
3. 联调回归：最终必须真实链路全量回归，重点看序列化、超时参数、鉴权这些契约文档写不清的细节。

### 分页 / 排序 / 过滤参数的用例设计框架
- 分页：0/1 起始语义、末页与超页、pageSize 上边界（传 10000 是变相 DoS）、游标伪造与过期。
- 排序：不存在字段、多字段优先级、排序字段注入（拼 SQL 即注入点）、同值排序稳定性（跨页重复/丢失）。
- 过滤：特殊字符、时间范围头尾包含性、多条件组合；全组合不现实，用 pairwise 或按风险挑高频组合。
- 统一加数据一致性断言：总数对得上、结果真的有序（代码验证而非肉眼）。

### gRPC 测试差异点
- proto 为纲：强类型，枚举 / oneof 边界重点测；工具链 grpcurl / Postman / grpcio。
- 错误断言按 gRPC status code 体系（UNAVAILABLE、DEADLINE_EXCEEDED）；流式接口的消息顺序、中途断开、背压是 REST 没有的维度；deadline 不传可能死等，超时用例必配。

## 性能测试

### TPS·RT·并发数换算与误区
- 利特尔法则：并发数 = TPS × RT(s)，仅用于估算起始并发，不可反推容量上限。
- 三个误区：RT 用平均值（应 P95/P99）；忽略加压机自身瓶颈；TPS 与 QPS 混用（一个事务可含多次请求，TPS ≤ QPS）。

### 流量建模与思考时间
- 思考时间缺失 = 机器人流量，TPS 虚高、容量结论作废。间隔按高斯或埋点实测，不用固定值。
- 真实建模四件套：间隔分布、混合场景（按生产流量比例分脚本组）、数据参数化（账号/商品从池取）、新旧用户登录态与缓存行为区分。

### 性能基线与压测排障
- 基线 = 固定环境 + 生产量级数据 + 固化脚本 + 多轮稳定值；对比先看 P95/P99 劣化（比均值更早暴露问题）。
- RT 涨 + CPU 涨 ≈ 低效代码；RT 涨 + CPU 平 ≈ 等锁/IO。连接池耗尽的表现：RT 跃升 + TPS 上不去 + CPU 不高 + 阶梯式错误率。
- 压测大量超时的分层定位：加压机 → 网关/限流 → 应用（线程池、GC）→ 数据库（慢查询、锁、连接池）→ 网络。

## 安全测试

### 命令注入测试要点
- 入口：文件处理、转码、ping 诊断等调系统命令的功能。
- payload 成套试：`;` `|` `&&` `||` 反引号 `$()` 换行符 + 无害探测（id / sleep 5）；用时间盲注与响应差异判定。
- 修复验证：确认 subprocess 列表参数 + shell=False，黑名单过滤不可靠。

### SSRF 测试方法
- 入口：URL 拉取、网页预览、webhook。危害核心是打内网与云元数据服务（169.254.169.254，授权范围内验证）。
- 分层验证：基础探测（127.0.0.1/内网段，看时间与报错差异）→ 协议面（file:// gopher:// dict://）→ 绕过面（DNS rebinding、302 跳内网、IP 进制变形、@ 混淆）。
- 修复验证：解析域名后再校验 IP（防 rebinding）、禁非 HTTP 协议、每跳重定向都校验。

### 敏感数据泄露检查清单（数据流五面）
1. 接口响应体：字段最小化、错误信息不带堆栈；
2. 应用日志：请求体 / token / 密码明文——最常见也最易漏的泄漏点；
3. 前端：localStorage、源码硬编码密钥；
4. 传输：全站 HTTPS；
5. 配置与 Git 历史：生产密钥、提交过的密码。
手法：正则扫响应与日志 + Burp 被动扫描 + 越权视角验证他人敏感字段。

## 自动化测试

### CI 失败四分法
1. 批量挂 → 环境问题（服务、配置、证书），推动巡检前置告警；
2. 本地过 CI 挂 → 环境/数据/并行差异；
3. 稳定挂且对应新提交 → 代码缺陷，提单；
4. 时好时坏 → flaky，进治理清单。
铁律：先看失败详情再分诊，禁止无脑重跑碰运气绿。

### Playwright vs Selenium 架构
- Selenium：WebDriver 协议经 driver 进程转发，链路长、版本匹配脆。
- Playwright：直连浏览器私有调试协议（CDP 等），自动等待（actionability check）内建，trace / network 录制开箱即用。新项目优先 Playwright，存量不强行迁移。

### 自动化报告的排查价值
- 报告的价值在失败时刻：5 分钟内让人知道「挂在哪、为什么挂、该谁看」。
- 必备：失败按原因聚类（断言/超时/元素/环境）、失败现场（截图 + trace + 关键接口响应）、环境快照、历史成败趋势（识别 flaky）。

## AI / Agent 测试

### 上下文窗口限制的测试设计
- 信息前置探针：开头给关键约束（如过敏信息），30 轮后再问，验证是否还记得——对抗截断遗忘。
- 指令漂移（长对话后段格式是否还遵守）、窗口边界（接近上限时质量断崖）、摘要压缩后行为差异。

### Token 成本评测三口径
- 单次成本（输入+输出，prompt 长度是输入大头）→ 回归全集消耗（每轮 CI 评测多少钱）→ 按调用量推算月度预算；超线触发 prompt 瘦身或换小模型。
- 延迟分 TTFT（首 token）与完整响应两个指标，按输入长度分桶统计。

### Agent Trace 字段清单
- 每步工具调用的参数（脱敏）、返回、耗时、成败——定位死循环与错误调用的核心数据。
- 上下文状态（轮次、token、检索命中）、决策依据（模型版本、temperature、兜底 reason）、session/trace id 全链路贯穿。
- 线上真实失败案例回填评测集，是最好的回归用例来源。

## 数据库 · Linux

### 事务 ACID 与验证动作
- 正向验证（中间态 + 最终态）、回滚验证（事务中间制造失败，确认无半截写入）、并发验证（超卖：库存 1 两个并发请求只许一个成功）。
- 隔离级别对应异常：读已提交防脏读；可重复读防脏读 + 不可重复读（InnoDB 间隙锁基本防幻读）。

### 数据库连接池
- 作用：摊销建连成本 + 限制并发连接总数保护 DB。
- 耗尽表现：RT 跃升（在排队等连接）、TPS 上不去但 CPU 不高、错误率随并发阶梯上升。
- 排查三样：maxPoolSize 配置、等待超时参数、连接泄漏或慢 SQL 长期占连接。

## 场景题

### 上线后核心接口 RT 翻倍
- 先止血再定位：影响面（全量/灰度）→ 变更倒查（回滚是否最快恢复）→ 分层监控比对（锁瓶颈层）→ 恢复验证 → 复盘（基线监控 + 上线前后对比补进流程）。
- 讲排查链条而不是拍结论，逻辑链和冷静度比技术细节更加分。

### 「这是 feature 不是 bug」
- 回需求文档 → 文档没写清找产品三方对齐 → 结论固化进用例库（同类争议不再发生）。
- 心态：目标是产品质量不是赢下争论；流程对了反而积累专业信任。

## 坑点精选

- 思考时间设 0，压出虚高 TPS——容量结论直接作废。
- 敏感数据只查响应体，漏了日志与前端存储——泄漏点根本没堵上。
- SSRF 只试一个内网 IP——DNS rebinding 一绕就破防。
- Mock 用完不复原——挡板切过去忘了切回来，后续用例全打到假服务上（用 fixture/with 保证复原）。
- 和开发争「是不是 bug」变成人际冲突——拿文档三方对齐，对事不对人。
