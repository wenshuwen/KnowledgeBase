# 面试原料精选 · 2026-09-16

> 来源：当日归档包 2026-09-16（3 组）精选。内容已脱敏：无项目名、产品名、真实域名/接口地址、账号与业务数据。

## 测试理论

### 测试计划 vs 测试方案
- 计划=管理维度（时间、人、准入准出、风险）；方案=技术维度（怎么测、工具、环境、数据策略）。
- 落地要点：计划一页化（里程碑+风险表），方案随迭代增量维护；小团队可合并，但管理线/技术线分开想。
- 面试加分句：「两者合并写没问题，但别把排期和用例设计方法混成一段。」

### 测试左移与测试右移
- 左移动作：需求评审提可测性、AC 拆解、BDD 场景先行、提测冒烟准入。
- 右移动作：灰度观察指标、线上拨测（核心接口定时巡检+异常进值班群）、日志监控告警。
- 结论句：左移防患、右移兜底，配套才是完整质量体系。

## 接口测试

### 接口幂等性测试
- 用例设计：重复提交（同幂等键 2~5 次，业务只生效一次）→ 并发重复（多线程/Locust 同时发）→ 失败重试（超时后重试不产生脏数据）→ 扣款成功响应超时后的对账验证。
- 关注点：区分「返回相同结果」和「真的没重复执行」；看幂等键实现（唯一索引/分布式锁/状态机）。

### 数据结构变更的快速感知（契约校验）
- 核心接口维护 JSON Schema，响应先过 schema 再断言业务；schema 进 CI 冒烟层，合流前拦截契约破坏。
- 报错人性化（直接报字段缺失/类型不符）；用 Swagger/OpenAPI 当契约源可省一份维护成本。

## 性能测试

### 「1000 并发」需求转可执行指标
- 转化链：用户量→在线峰值→并发请求→TPS 目标；二八原则估算峰值 TPS 后乘 3~5 倍冗余。
- 指标=负载模型+通过标准：目标 TPS 下 RT P95、错误率<0.1%、资源水位<70%。

### 稳定性（疲劳）测试
- 中等负载（日常峰值 70%~80%）持续 8~24h+，抓时间累积类问题：内存/句柄泄漏、连接膨胀、GC 恶化、日志撑爆磁盘。
- 关键动作：对比测试前后资源基线曲线，单调上涨即追查。

## 自动化测试

### 框架失败取证机制（日志+截图）
- 原则「失败现场自解释」：pytest_runtest_makereport hook 里统一执行——UI 截图+DOM/URL，接口落盘完整请求响应+curl 重放命令，产物进 Allure attachment。

### PO 之上的业务流程层
- 四层：元素层（PO）→业务层（login_flow/create_order_flow）→用例层（禁定位器）→数据层。
- 分层合理性判据：需求变更要改的地方是否足够少。

## 安全测试

### 越权测试（水平/垂直）
- 双账号矩阵法：A 的 token 访问 B 的资源 ID，看服务端是否校验归属；低权 token 重放管理员接口；ID 连续时验证可枚举性；不带 token 验未授权。
- 工具：Burp Autorize 自动比对高权/低权响应。注意测试环境+假数据+测后清理。

### 防爆破机制测试点
- 验证码：可复用、可绕过（响应泄露/前端校验）、过期与错误次数、短信轰炸（60s/日上限）。
- 限流：阈值生效（429）、按 IP/账号维度绕过、恢复机制、误伤评估。账号锁定：N 次锁定、时长、重置密码绕过。

## AI 测试

### LLM 评测集设计
- 四步：圈场景→造样本（常规/边界/对抗/badcase 回流）→定判法（规则断言+LLM-as-judge+人工抽检三层）→立基线（分数下降超阈值阻断发布）。
- 维度：准确性/相关性/完整性/格式/安全性/一致性。核心心得：评测集是活资产，badcase 持续回流。

### 采样参数与随机性处理
- 回归固定 temperature=0；断言「不变式」（结构/关键词/语义相似度/业务规则）而非全文匹配；关键场景 5~10 次采样用通过率；支持 seed 则固定。
- 加分句：「随机性不是噪音，是被测能力的一部分，要测的是分布质量。」

## AI Agent 测试

### 规划能力测试
- 拆得对：子任务完备性/顺序依赖/粒度，用 rubric+judge 评；走得通：全程记录动作与中间产物，三类异常信号——中间产物错误、步数异常（5 步任务跑 20 步）、结果与路径矛盾。
- 容错：Mock 某步失败，验证重规划而非硬跑。核心句：过程轨迹才是规划能力的主要证据。

### 多 Agent 协作测试
- 单体先行→协作协议（交接完整性/角色边界/死锁）→故障注入验证失败传播：隔离、重试还是被污染（错误放大）。
- 指标：任务成功率之外重点看轮次效率与错误放大率。

## Python

### 深浅拷贝在测试脚本里的坑
- 浅拷贝（a[:]、dict.copy()）内层共享引用；三个高发坑：可变默认参数 def f(data=[])、共享请求体 dict 被上游用例污染（flaky 来源）、浅拷贝后改内层污染断言基线。
- 解法：用例级 deepcopy 基础数据；排查用 id()+内容打印对比。

### fixture vs setup/teardown
- 优势：按需注入、依赖链、作用域四档（session 级省昂贵初始化）；yield 分界 setup/teardown，用例失败清理也执行；conftest 跨文件共享。

## 数据库 · Linux

### 索引失效口诀与排查
- 口诀：函数运算、隐式转换、前导模糊、OR 混搭、不满足最左前缀。
- 排查：EXPLAIN 四列（type/key/rows/Extra）→统计信息过期→联合索引顺序→改写 SQL/补索引。测试场景另关注深分页与大批量 UPDATE 锁表。

### 事务隔离级别的测试验证
- 双会话并发实验：A 写不提交/提交/插入，B 分别读，验证脏读、不可重复读、幻影行；落到资金/库存类业务设计并发扣减用例。

## 场景题

### 带病上线的决策框架
- 五依据：影响面、严重度与劣化趋势、修复风险、业务窗口、兜底手段（开关屏蔽）。
- 立场句：测试举证（影响面+风险），拍板是业务的权力。

### 偶现问题排查套路
- 最小上下文→traceId 全链路捞日志→放大复现（同数据重放/并发/弱网）→观测增强（埋点/debug 日志）→防御性修复。
- 反模式：「复现不了就关单」。

## CI/CD

### 测试环节流水线编排
- lint→单测→接口自动化（docker 起依赖）→UI 冒烟→nightly 全量回归；快的在前 fail fast，贵的定时/核心分支触发；每阶段设超时与门禁。

### 「构建挂了没人管」的推动三板斧
- 止血重建可信度→失败通知定位到人（git blame）+升级规则→晨会播报构建健康度（成功率/MTTR）。
- 核心：红灯必须有人认领、认领必须低成本、不响应有后果。
