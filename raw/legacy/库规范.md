- 网页文章 → 原文存 `原文库/01-文章网页/`（保留原链接）

## 二、两条死规矩（来自用户，永久生效）

### 规矩 1：链接一律 `[[文件名]]`
- 引用任何笔记只用 `[[文件名]]`，**禁止**带路径/斜杠/扩展名（如 `笔记/04-自动化测试/xx.md` 是错误示范）。
- 只有三种例外允许出现路径文字：目录树示意图、正文叙述中描述"文件放在哪里"、代码块里的示例。这些情况不算"引用跳转"。
- 为保证 `[[文件名]]` 能解析：**全库文件名必须唯一**。重名时：若是同一主题 → 合并；若是不同内容 → 改名区分（如加日期/项目名前缀）。

### 规矩 2：入库四件事，缺一不可
每入库一篇内容，依次完成：
1. **存原文** → `原文库/` 对应子目录（原样，不改）。若原文来自链接且无文件，则在 `01-文章网页` 存一份含原链接、作者、日期的存档 markdown。
2. **写笔记** → `笔记/` 对应分类下新建笔记（结构见下），正文中标注「来源：对应原文存档」（用 `[[双链]]` 指向 [[01-文章网页]]、[[02-截图日志]]、[[03-需求原文]] 中的实际存档条目）。
3. **更新目录** → 在 [[总目录]] 对应分区表格插入一行；刷新对应分类入口页的「笔记列表」。
4. **记流水账** → [[流水账]] 追加一行。

## 三、笔记模板

```markdown
---
type: note            # note / problem / project / interview
tags: [分类标签]       # 例：[自动化测试] [接口测试]
created: YYYY-MM-DD
updated: YYYY-MM-DD
source: 原文文件名或URL
---

# 标题

## 背景 / 上下文
（为什么会有这篇：问题来源、当时的场景、需求背景——保留"原因"）

## 要点 / 做法
（核心内容，步骤化、清单化，便于速查）

## 细节现场
（报错日志、截图引用、关键参数、复现步骤——原样保留）

## 相关笔记
- [[05-接口测试]]（示例：指向真实存在的笔记）
- [[03-原文存档文件名]]
```

**AI 维护规则：** 每次入库后把 `updated` 同步为当天日期；引用了新原文就补 `source`。

## 四、需求→测试设计工作流（09-项目经验 专用）

用户的特殊用途：**用需求知识库生成测试用例、覆盖测试点、做需求评审、补测试场景**。因此：

- `原文库/03-需求原文/` 必须保存**完整未删减**的需求原文（含细节要求），不可只留摘要。
- `09-项目经验/<项目>/` 下的笔记要区分：`需求理解`（拆解业务规则、边界、隐含需求）、`测试点清单`、`评审问题记录`、`测试场景补充`。
- 生成测试用例时优先引用 [[03-需求原文]] 归档，标注每个用例覆盖的需求点编号。

## 六、需要"先问用户"的情况

1. 内容是否入库存在歧义（用户说过：常见问题/经典场景/坑点要**先询问**再决定是否保存）。
2. 重名笔记要合并或拆分。
3. 原文要不要保留（涉及隐私/版权）。
4. 结构化提取出错、理解有偏差时先澄清。

## 七、Obsidian 适配约定

- 所有笔记为 `.md`，Obsidian 可直接打开。
- Frontmatter（`---` 包裹的 YAML）供 Obsidian 属性面板/检索使用，`tags` 保持精简（≤5 个）。
- 文件名避免特殊字符：空格、`/`、`\`、`#`、`[`、`]` 一律不用（中文、`-`、`_` 可用）。
- 图片/附件：Obsidian 默认库内附件；截图原件放 `原文库/02-截图日志/` 并在笔记里用 `![[文件名.png]]` 引用。
