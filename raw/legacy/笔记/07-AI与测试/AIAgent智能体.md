# AI Agent 智能体原理

> 📌 来源：[[Test-测试经验总结-原文]] ｜ AI章-Agent 小节

AI Agent 的底层框架，本质上是一个围绕大语言模型（LLM）构建的、能够自主感知环境、进行推理决策并执行行动的循环系统。它的核心目标，是让 LLM 从一个只会“思考”和“对话”的大脑，进化为一个能“动手”解决实际问题的智能体。

简单来说是一个具备状态感知、任务分解、上下文记忆、工具交互与自主规划能力的复杂系统工程。

## **2\.1 核心架构**

一个典型的 AI Agent 框架，通常由以下四大模块构成，它们协同工作，构成了 Agent 的完整能力。

- **大脑（规划与推理模块 \- Planning \& Reasoning）**：这是 Agent 的决策中心。它负责理解复杂任务，并将其拆解为可执行的子任务（任务分解），并决定为了完成每一步，需要调用什么工具或采取什么行动。这依赖于像 ReAct、Plan\-and\-Execute 等高级推理模式。

- **记忆（记忆模块 \- Memory）**：让 Agent 具备“记性”的模块。

    - 短期记忆：即当前对话的上下文，受限于模型的上下文窗口长度，相当于人类的短期工作记忆。

    - 长期记忆：通常通过向量数据库存储在外部，支持长时间保留和快速检索，让 Agent 能“记住”过去的经验和知识。

- **手脚（工具与执行模块 \- Tools \& Action）**：Agent 与外部世界交互的接口。通过工具调用（如 Function Calling, MCP 协议），Agent 可以执行代码、搜索信息、操作文件或调用任何 API，从而突破 LLM 本身的知识和能力限制。

- **角色（角色/配置文件模块 \- Profile）**：通过系统提示词等上下文工程，为 Agent 设定一个特定的身份、目标和行为准则，使其在不同场景下能以特定风格和方式行事。

## **2\.2 工作原理**

AI Agent 的运行并非线性的“一问一答”，而是采用“**感知\-规划\-行动\-反思**”的四阶循环模型：

- **感知阶段**：解析用户的显式需求与隐式约束，扫描系统资源状态，并从记忆系统中回溯相关历史经验。

- **规划阶段**：采用分层决策机制，为总目标生成包含里程碑的执行计划树，并预设故障处理的应急规划。

- **行动阶段**：根据计划协同调用工具链，执行具体操作，并将结果标准化反馈给系统。

- **反思阶段（Reflection）**：这是 Agent 的“元认知能力”。它会对比预期与实际输出，进行误差分析。若执行失败，Agent 会主动修正策略或尝试其他方法，并将新经验写入长期记忆以实现自我优化。

## **2\.3 基础设施（Harness）**

在实际的工业级落地中，单纯的裸模型存在无记忆、不能执行代码、知识过时等局限。因此，Agent 的底层框架通常包含一套被称为 Harness（工程基础设施） 的系统化方案，核心公式为：**Agent = Model \+ Harness**。

Harness 旨在弥补裸模型的缺陷，其底层关键支撑包括：

- 沙箱与代码执行环境：提供安全隔离的工作空间（如 Bash 沙箱），赋予 Agent 代码执行和自我验证的能力。

- 上下文工程：这是当前 Agent 应用的核心与“低垂的果实”。它精细地管理着每次输入给 LLM 的上下文内容，包括系统指令（角色设定）、用户问题、过往对话历史、工具返回的结果，甚至是从长期记忆中检索到的相关信息。研究表明，在不提供任何有效上下文的情况下，最先进的模型仅能解决不到 1%的任务，足见其重要性。通过压缩、工具输出卸载等策略，对抗长对话中的“上下文腐烂”，管理模型的输入窗口。

- 安全与权限控制：解决“谁可以访问 Agent”以及“Agent 可以访问哪些资源”的双重身份问题，实施细粒度的权限隔离与安全防护。

- 可观测性（AgentOps）：追踪推理链路、监控工具调用的合理性，实现思维过程的可视化，以便于调试和持续优化。

> ***综上所述，AI Agent 的底层框架是一个由大模型驱动，融合了记忆管理、动态规划、工具调用和自我反思的复杂系统。它通过工程化的基础设施（Harness）保障运行的安全与稳定，最终实现从被动响应指令到主动完成复杂目标的跨越。***

|组成部分|核心作用|关键技术/示例|
|---|---|---|
|🧠 核心大脑 \(LLM\)|负责理解语言、进行推理和决策，是 Agent 的“思考”中枢。|大型语言模型，如 GPT 系列、Claude、Llama 等。|
|🧭 规划与推理模块|将复杂目标拆解为可执行的步骤，并动态调整计划，是 Agent 的“战略家”。|ReAct（推理\+行动）、思维链（CoT）等技术。|

|🔧 工具与技能模块|让 Agent 能与外部世界交互，执行具体操作，是 Agent 的“手和脚”。|API 调用（如查询数据库、发送邮件）、网络搜索、代码解释器等。|
|🎼 协调器 \(Orchestrator\)|负责调度和协调所有模块，管理工作流程，决定何时调用工具、检索记忆或寻求人类帮助。|工作流引擎、LangChain、Semantic Kernel 等框架。|
