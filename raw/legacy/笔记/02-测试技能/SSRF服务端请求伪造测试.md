# SSRF 服务端请求伪造测试

> 📌 来源：[[Test-测试经验总结-原文]] ｜ 安全测试章-SSRF 小节

服务端提供了"从指定 URL 获取资源"的功能，但未对目标地址进行严格校验，导致攻击者可控制服务端发起任意 HTTP/TCP 请求，诱导服务器向任意目标地址发起 HTTP 请求，从而访问或探测服务器所在内网的资源。

**高危功能点（测试入口）：**

- URL 预览 / 链接分享解析

- 图片抓取 / 头像上传 / PDF 生成

- Webhook 回调地址配置

- XML/JSON 外部实体引用

- 导入远程资源（RSS、CSV、模板）

- SSO/OAuth 回调验证

- 云服务元数据接口调用

---

**SSRF 测试详解示例**

```HTTP
POST /api/fetch HTTP/1.1
Host: example.com
Content-Type: application/json

{"url": "https://example.com/image.jpg"}
```

- **测试步骤（由浅入深）**

|步骤|测试 Payload|目的|判定标准|
|---|---|---|---|
|1|`http://127.0.0.1:80/`|探测本地回环地址是否可达|返回本地服务页面内容，或响应时间/状态码异常|
|2|`http://169.254.169.254/latest/meta-data/`|探测云环境元数据服务（AWS/阿里云等）|返回云服务器的实例身份信息（AK/SK 等）|
|3|`http://192.168.1.1:8080/admin`|探测内网常见 Web 管理后台|返回内网后台 HTML 或错误信息|
|4|`file:///etc/passwd`|尝试读取本地文件（伪协议利用）|返回文件内容|
|5|`http://internal-redis:6379/`|探测内部服务（如 Redis、Elasticsearch）|根据响应时间或返回内容判断端口开放情况|

- **SSRF 的多种利用方式**

|利用方向|示例|危害等级|
|---|---|---|
|内网端口扫描|遍历 `http://10.0.0.1:22` \~ `http://10.0.0.1:8080`|🔶 中（信息收集）|
|读取本地文件|`file:///etc/shadow`|🔴 高（敏感文件泄露）|
|攻击内网服务|向内网 Redis 发送恶意命令（利用 Gopher 协议）|🔴 极高（可实现 RCE）|
|云元数据窃取|`http://169.254.169.254/latest/meta-data/iam/security-credentials/`|🔴 极高（接管云账号）|
|绕过防火墙/ACL|利用 SSRF 访问被防火墙隔离的内部系统|🔴 高|

---

> **SSRF 防御方案**
> 
> 

1. **黑白名单策略**

- 白名单（推荐）：只允许访问预先批准的域名/IP 列表。

- 黑名单（不推荐，容易被绕过）：禁止内网 IP、127\.0\.0\.1 等。

2. **过滤伪协议**

限制只允许 `http://` 和 `https://`，禁止 `file://`、`gopher://`、`dict://` 等协议。

3. **服务端限制**

- 设置 HTTP 客户端禁止重定向，防止利用跳转绕过。

- 设置超时时间，避免被拖死。

- 对返回内容做过滤，防止敏感信息回显。

4. **统一访问入口**

避免用户直接传入完整 URL，改为传入资源 ID，服务端映射到固定路径。
