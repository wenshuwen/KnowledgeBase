# Nmon 系统监控工具

> 📌 来源：[[Test-测试经验总结-原文]] ｜ 测试工具章-Nmon 小节

nmon（Nigel’s Monitor）是一款由 IBM 工程师开发的、专为 Linux 和 AIX 系统设计的轻量级系统性能监控工具。它能够实时捕捉并记录系统资源的使用情况，广泛应用于生产环境的服务器性能基线建立、故障排查、容量规划与性能调优等关键运维场景。

## 🖥️ 核心优势与监控维度

nmon 具有极低的系统开销（通常 CPU 占用率低于 0\.5%），且无需复杂的配置即可使用。它能够全面监控以下核心指标：

- CPU 使用率：包括用户态、系统态、等待 I/O 及空闲状态等细分指标。

- 内存使用情况：物理内存、交换空间（Swap）、缓存（Cache）及缓冲区等。

- 磁盘 I/O：磁盘读写速率、传输比率、繁忙率及 I/O 队列信息。

- 网络 I/O：网络接口的收发速率、数据包数及错误/冲突统计。

- 进程统计：消耗资源最多的进程及内核运行队列信息。

## 🤖 安装与基本交互

> 1. **安装**
> 
> 

在大多数 Linux 发行版中，可通过包管理器直接安装：

- Ubuntu 系统：`apt install nmon`

- CentOS 系统：`yum install nmon`

> 2. **交互式实时监控**
> 
> 

在终端直接输入 `nmon` 即可进入实时交互界面。在界面中，可通过以下快捷键切换监控视图：

- `c`：查看 CPU 使用率

- `m`：查看内存信息

- `d`：查看磁盘 I/O 状态

- `n`：查看网络流量

- `t`：查看进程资源占用（类似 top 命令）

- `h`：显示帮助菜单

- `q`：退出 nmon 界面

> 3. **非交互式数据录制（历史复盘）**
> 
> 

通过组合参数，可以让 nmon 在后台自动采集数据：

```Shell
nmon -f -s 5 -c 60 -m /data/nmon -t
```

参数说明：

- `-f`：按标准格式输出文件，文件名默认包含主机名和时间戳`hostname_YYMMDD_HHMM.nmon`。

- `-s 5`：每隔 5 秒采集一次数据，采集间隔时间，默认 2 秒。

- `-c 60`：总共采集 60 次（即持续监控 5 分钟），采集次数，与`-s`共同决定总时长。

- `-m /data/nmon`：指定生成的数据文件存放目录。

- `-t`：在导出的信息中包含高耗能的进程信息。

> 4. **长时间后台录制（无人值守监控）**
> 
> 

```Shell
# 若需进行长期的性能基线收集，可结合 nohup 让nmon在后台运行：
nohup nmon -f -s 10 -m /data/nmon --csv &
```

*说明*：此命令每 10 秒采集一次数据并无限采集。如需提前终止，可通过 `ps aux | grep nmon` 找到进程 ID，然后使用 `kill -9 进程ID` 强制停止。

> **计算公式：总监控时长 = ****`-s`**** × ****`-c`****。例如****`-s 30 -c 120`****表示每 30 秒采一次，共 120 次，总计监控 1 小时。**
> 
> 

## 📈 数据分析与图形化

采集得到的`.nmon`文件是文本格式，不便直接阅读，需借助 nmon analyser \(Excel 宏工具\) 生成图表。

分析步骤：

- 下载工具：获取 `nmon analyser` \(如 `nmon_analyser_v69.xlsm`\)。

- 准备文件：将服务器上的`.nmon`文件下载到本地电脑。

- 打开工具并启用宏：用 Excel 打开`.xlsm`文件，务必点击“启用宏”。

- 导入数据：点击 `Analyze nmon data` 按钮，选择下载的`.nmon`文件。

- 查看图表：工具自动生成新 Excel 文件，包含 `CPU_ALL`、`MEM`、`DISK`、`NET` 等图表页，可直接复制使用。

常见瓶颈分析：

- CPU 瓶颈：在`CPU_ALL`表中，若`%idle`（空闲率）长期低于 20%，说明 CPU 繁忙。

- 内存压力：在`MEM`表中，若`memfree`（空闲内存）持续接近 0，同时`swap`\(虚拟内存\)写入频繁，说明物理内存不足。

- 磁盘 I/O 瓶颈：在`DISK`表中，若某磁盘`busy`值持续很高，说明该盘存在 I/O 瓶颈。

## 💡 注意事项与误区

- 文件大小限制：不建议对长时间的稳定性测试使用 nmon 监控。当生成的 nmon 文件超过 10M 时，分析工具可能会因内存不足而报错。若必须长时间监控，建议加大采样频次（如 `-s 30`）并降低总采样次数。

- 不支持回放：nmon 的交互式界面仅支持实时查看，不支持历史数据回放。历史数据必须通过导出文件并使用分析工具查看。

- 工具互补：虽然 nmon 功能强大，但无法监控 JVM 内存（堆内存、GC 等），监控 Java 应用需结合 jstat、VisualVM 等专用工具。同时，若对实时性要求高，可结合`top`或`htop`命令辅助判断。
