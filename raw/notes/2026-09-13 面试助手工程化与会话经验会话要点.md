## 一、技术审计发现（真实问题，非风格问题）

1. **构建"先写产物、后定退出码"（fail-open）**：检测到未转义 HTML / 死链时产物已经落盘，
   检测结果只剩一个退出码。修法：判定先于写入，检出危险内容拒绝落盘。
2. **`publish` 开关用 `is False` 严格判定**：frontmatter 写成 `"false"` / `0` / `'0'` 时
   YAML 解析成字符串或数字，严格同一性判定直接放行 → 页面静默上站。
   修法：宽松识别可疑写法（一律按未发布处理）+ 显式告警。隐私开关方向不能反。
3. **死链检测不区分"目标不存在"与"目标存在但不上站"**：后者在站点上是可点但点不通的胶囊。
   据此发现了 2 条线上真实空链接。
4. **搜索无防抖**：输入框直连检索，归档多版本时每次输入全量重算。
5. **空数组未兜底**：`arr[i % 0]` 产生 NaN 下标 → undefined → 渲染整块抛异常，
   且被 try/catch 吞掉，用户只看到空白。

## 二、「按日期 × 按组」归档设计

- 一天一个包，包内 N 组；每组条数有下限（自动化生成目标即测试断言）
- **索引记录「日期 → 所在文件名」**，前端只读索引、不拼路径 ——
  跨月合并后同一天会从 `YYYY-MM-DD.json` 换到 `YYYY-MM.json`，猜路径在合并当天全线 404
- 保留策略：当月按日、跨月合并成月文件（幂等）；合并时必须同步改索引指向
- GitHub 热点按「天」不按「组」（当日排行榜快照，分组会导致采集量翻倍且无意义）

## 三、发布机制

- **发布判据是"本地与线上哈希不一致"，不是"某条数据通道变化了"** ——
  只认内容包变化会让页面代码的更新永远发不出去（真实发生过）
- 发布后必须复核文件哈希；只看 HTTP 200 会漏掉「JS 新、CSS 旧」的半新半旧推送
- 三层保障：会话内立即发布 → 每日定时按漂移判据发布 → 只读巡检（先跑回归测试才发）

## 四、两套分类词汇

- **wiki frontmatter**：长键（`api-testing` / `performance-testing` …），构建脚本合法性校验用
- **站点归档条目**：短键（`api` / `perf` …），与前端分类字典一致
- 混用的后果：前端标签显示成原始英文键。需要一条"两套词表键集合一致"的回归测试钉住
- 归档 → wiki 编译落点靠映射表；部分短键（语言基础、场景题、软技能）暂无明确落点，标记待定

## 五、命令行与无头浏览器踩坑（macOS）

1. BSD grep 的 BRE 不支持 `\|` 交替 —— 多模式匹配静默返回 0 条假结果，用 `grep -E` 或逐个 `grep -cF`
2. `git add` 任一路径不存在会**整体失败**、不部分执行 —— 删除过的文件留在 add 列表里会拖垮整条命令
3. 无头 Chrome 在受限环境必须 `--no-sandbox`，否则 `--dump-dom` 输出 0 字节
4. 验证移动端视口必须用真实视口（`--window-size`）；强制元素宽度**不触发 `@media`**，溢出全是假阳性
5. 插桩探针要放在页面初始化调用之前，否则被吞掉的告警抓不到；本地 HTTP 服务必须常驻

## 六、工程判断（可复用）

- **"检测到了但拦不住"比"检测不到"更危险**：防线给了错觉，实际敞开
- **外部采集数据的外链必须过 scheme 白名单**（只放行可信域名），一条 `javascript:` 就是真实注入
- **数据格式改动必须同步所有消费方**：内嵌兜底、渲染代码、契约校验、测试四处一致
- **内容流水与知识图谱必须分层**：图谱每页要抽实体、补链、控孤页率；直接灌流水会冲垮图谱，
  折中是"每日落原料（只增不改+脱敏）、低频按图谱标准消化"
