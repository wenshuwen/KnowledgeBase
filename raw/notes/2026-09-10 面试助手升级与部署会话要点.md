## 一、原始诉求

以本地知识库作为底层数据源，开发面试助手：
1. 接入本地知识库内容作为数据源
2. 每天定时从线上获取面试题材并写入知识库
3. 面试助手以静态网站形式渲染展示
4. 支持多端浏览

并要求"参考之前已实现的面试助手项目，保持整体架构与已有实现一致"。

## 二、对诉求的可行性与冲突判断

| 需求 | 判断 | 依据 |
|---|---|---|
| ① 接入知识库为数据源 | 可行，但需新增构建步骤 | 浏览器读不到本地文件系统 |
| ② 每天抓取写入知识库 | **照字面实现会毁库** | 与知识库铁律冲突：单源精读、自动抓取须过人工确认闸门、页面须有交叉引用 |
| ③ 静态站点渲染 | 已具备 | 现站就是静态单文件 + 运行时拉内容包 |
| ④ 多端浏览 | 已具备 | viewport 响应式 + 微信 X5 兼容已做过 + 公网链接 |

**需求 ② 的具体风险**：每天自动往 wiki/ 灌素材，一年 3000+ 条外部内容会淹掉个人经验图谱；自动内容不会自己长交叉引用，会批量制造孤页，击穿"孤页率 <5%"的健康指标；无人确认则质量问题无回收口。

**改造后的形态**：抓取素材只落 `raw/interview/`（原料层，自动写入天经地义），编译进 wiki 每日限 1–2 页。流水层与沉淀层分离。

## 三、发现的两套规范冲突

- `~/WorkBuddy/知识库/`：旧 Obsidian 库，91 篇笔记，自带 `库规范.md`
- `~/WorkBuddy/KnowledgeBase/`：新建的编译式知识库，自带 `WIKI-SCHEMA.md`

两套规范并存会让 agent 按不同标准干活。**决策：以新库为唯一数据源**，旧库 91 篇降级为原料（导入 `raw/legacy/`，排除 vault 元文件与插件技能后 67 篇）。

## 四、四条锁定的设计决策

| 决策点 | 结论 |
|---|---|
| 数据源 | 新库为唯一数据源，旧库导入 raw/legacy 当原料 |
| 素材流向 | 原始素材落 raw/，编译后进 wiki/；站点按模板渲染 |
| 页面粒度 | 复用现有 6 类模板，不新增模板类型，改为扩展 frontmatter |
| 公开范围 | frontmatter 加 publish 开关，默认 true |

## 五、实施过程中的关键取舍

1. **kb.json 走平行通道，不扩 content.json**。主包已 145KB，再塞会拖慢首屏；而微信 X5 首屏解析本就弱。平行文件还带来隔离红利：知识库编译失败不影响每日复习内容管道。
2. **面试内容页不集中堆进专属目录**。内容归档到各领域目录（性能题进 30-性能测试/），`75-面试助手/` 只放索引与专题页。理由：集中会切断与同领域概念页的链接，图谱价值腰斩。
3. **分类键做映射层而非改数据**。kb.json 用长键（performance-testing），站内用短键（perf），在渲染前做一层 `KB_CAT_MAP`，直接复用现有标签样式，零样式改动。
4. **入口初始隐藏**。知识库 tab 默认 `display:none`，只有 kb.json 拉取成功才放出。失败静默降级——实测在本地预览环境（取不到 kb.json）主功能完全不受影响。

## 六、踩到的坑

### 坑 1：publish 过滤的位置

**必须只在构建脚本里过滤。** 前端过滤意味着内容已下载到浏览器，等同于已公开，开关形同虚设。
验证方式：断言未发布页的**正文文本**不出现在产物文件里（只断言"列表里没有"不够）。

### 坑 2：受限目录下 git 无法初始化

`/Users/tigerwen/WorkBuddy/2026-09-02-22-53-01/` 下 `git init` 报：
```
error: could not write config file .../.git/config: Operation not permitted
```
- 普通文件写入与删除在该目录正常，同目录 rename 也正常
- 加沙箱豁免重试无效 → 不是工具层问题，是目录级限制
- 首次失败会残留 `.git/config.lock`，后续重试会被它绊住

**解法**：`git init --separate-git-dir=/Users/tigerwen/WorkBuddy/.git-interview-assistant`，把版本库元数据放到仓库外。日常 `git` 命令无感。

### 坑 3：批量编辑模板时吞掉章节标题

用 Edit 工具替换一段连续文本时，old_string 多带了一行标题，导致目录结构被删。教训：**替换块的首尾边界要精确到不产生歧义的唯一串**，替换后立刻读回校验。

## 七、自动化串联的形态

原每日任务只做内容包更新，扩展为三段：

1. 抓取素材 → `raw/interview/<日期>.md`（不可变、强制脱敏）
2. 精选 1–2 页单源精读编译进 wiki（强制渲染契约字段、强制 ≥2 出链）
3. 跑构建脚本 → 待修清零 → 记 log → 提交两个仓库 → 重新部署

失败隔离：知识库三段任一失败，不影响每日复习输出与内容包更新。

另修正一处历史遗留：prompt 里"周日或超 7 天触发内容包更新"与用户已变更的"每日必触发"不一致，已同步。
