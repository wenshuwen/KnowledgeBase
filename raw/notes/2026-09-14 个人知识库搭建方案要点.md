# 个人知识库搭建方案要点

> 来源：2026-09-14 会话（用户提问「系统列举当前主流且核心的个人知识库搭建方案」）
> 性质：对话回填原料（双方共同经历，要点无歧义），供 `wiki/76-问答沉淀/个人知识库搭建方案全景对比.md` 溯源
> 脱敏检查：无项目名、产品名、真实域名、账号、业务数据、凭据

---

## 一、分类框架（本次讨论的核心判断）

两条正交轴：

1. **自持度** —— 数据存在哪、归谁控制、能否整体搬走
2. **协作度** —— 谁来维护、几个人同时用

这两轴直接决定成本结构：

- 自持度高 → **现金成本低、时间成本高**（维护、整理、备份全靠自己）
- 协作度强 → **省人力，但订阅费与供应商锁定成本随规模线性增长**

结论：**当前没有一种方案能同时占住「高自持 + 高协作」**，选型必须先认下这个互斥。

## 二、七类方案要点

### 1. 本地纯文件 / 本地优先 Markdown
- 代表：Obsidian、思源、纯文件夹 + 任意编辑器
- 优势：零订阅；纯文本可被任何编辑器与 agent 直接读写（无需 API）；离线可用；可 Git 版本化；迁移成本 < 5%
- 劣势：多人实时协作几乎为零；插件折腾是时间黑洞；移动端体验一般
- 人群：个人长期沉淀、开发者、要给 AI 喂料的人
- 成本：现金 ≈ 0（Sync 约 ¥30/月、Publish 约 ¥55/月，均可选）；主成本是**整理时间**

### 2. docs-as-code（Git + 静态站生成）
- 代表：Git + MkDocs / Docusaurus + CI
- 优势：文档与代码同流程（PR 评审、CI 构建）；发布即静态站；天然版本化；搜索可接 Pagefind / Algolia
- 劣势：写作门槛（Markdown + Git）；非技术同事基本用不了
- 人群：工程团队、技术文档、需要对外发布的个人
- 成本：现金 ¥0–300/年（域名可省）；人力 20–40 h/年维护构建链路

### 3. 云端笔记 SaaS
- 代表：Notion、语雀、飞书文档
- 优势：开箱即用；协作与权限成熟；数据库视图与模板丰富；跨端同步省心
- 劣势：数据不在自己手里；**迁移成本 20–40%**（relation / rollup 会丢）；按人头订阅随规模线性上涨；AI 能力要加钱
- 人群：协作优先、不愿运维的人
- 成本：个人 ¥0–70/月；含 AI 约 ¥140/月；20 人团队 ¥1.7 万–5 万/年

### 4. 自建 Wiki 服务端
- 代表：Wiki.js、BookStack、Outline、Docmost、Trilium
- 优势：数据自持 + 多人协作可兼得；权限 / SSO / 搜索完全可控；Wiki.js 支持 Git 后端双写
- 劣势：DevOps 成本真实（Outline 需 App + PostgreSQL + Redis + S3 四个服务）；升级、备份、故障全归自己；个人使用属过度工程
- 人群：10–100 人技术团队、有运维能力的组织
- 成本：VPS ¥70–430/月 + 域名备份；**人力 ¥3 万–10 万/年（主项）**

### 5. 企业级项目知识库
- 代表：Confluence、飞书企业版、SharePoint、语雀企业版
- 优势：合规审计；权限体系；与工单 / CI / 项目打通；有厂商支持与 SLA
- 劣势：贵、重、僵化；数据迁出很难；小团队用不动
- 人群：中大型企业、有采购与合规要求
- 成本：¥100–500/人/年起，含实施与培训首年常 10 万+

### 6. AI 原生 / RAG 知识库
- 代表：Dify、RAGFlow、FastGPT、MaxKB、AnythingLLM
- 优势：自然语言问答；自动切片建索引；可接工作流与 Agent
- 劣势：**回答质量完全取决于原料质量**，答错还很难察觉；切片与 embedding 重建是持续性运维；模型调用费随用量浮动；本质是「问答引擎」而非「知识本体」
- 人群：需要问答入口的团队、资料阅读场景
- 成本：软件免费，但服务器 / GPU 或 API 合计 ¥2,000–3 万/年

### 7. LLM 编译式知识库（llm-wiki 范式）
- 特征：只存 Markdown，由 LLM 在投喂时完成编译（交叉引用、矛盾标注就位）
- 优势：回答带来源可追溯；纯 Markdown 天然自持；agent 直读文件系统、不依赖任何 API；好答案可回填成新页，形成复利
- 劣势：依赖「单源精读」的投喂纪律，批量灌入会让交叉引用质量崩塌；强依赖一个可靠 agent；多人协作同样弱
- 人群：个人精耕、要「经验图谱」而非收藏夹的人
- 成本：现金只有模型 token（¥300–1,500/年）；主投入是**纪律与时间**

## 三、成本量级（年现金支出，2026-09 估算，以官网为准）

| 方案 | 年现金支出 |
|---|---|
| 本地 Markdown + Git | ≈ ¥0 |
| docs-as-code 静态托管 | ≈ ¥150 |
| 笔记 SaaS · 个人版 | ≈ ¥850 |
| 自建 Wiki · 单机 VPS | ≈ ¥1,000 |
| 笔记 SaaS · 含 AI 套餐 | ≈ ¥1,700 |
| 自建 Wiki · 小团队 | ≈ ¥4,200 |
| AI / RAG 自建 · 含模型调用 | ≈ ¥9,000 |
| 企业 SaaS（20 人） | ≈ ¥3.3 万 |

汇率口径：1 USD ≈ ¥7.1。上表只含现金，不含自身时间。

## 四、结论

- **综合成本最低**：本地 Markdown 纯文件 + Git。现金趋近 0；无服务器、无订阅、无供应商绑定；备份即复制目录；**迁移成本实质为 0**（本身就是标准格式）。其他方案都有某个环节会随时间变贵或不可用（涨价、改版、停服、升级路径断裂、导出丢关系）。
- **最推荐**：本地 Markdown 单源 + Git 版本控制 + LLM 辅助编译，需要分享时再挂一层静态站。四条理由：
  1. 成本结构最优 —— 付的是自己的时间，而这份时间会复利；订阅制付固定租金，不产生资产
  2. 格式最优 —— 纯文本是唯一能被所有编辑器、所有模型、所有未来软件读取的格式，一份投入多处收益
  3. 可渐进 —— 要图谱挂 Obsidian，要对外挂静态站，要问答加检索，要协作上 Wiki.js / Outline；数据层全程不动
  4. 唯一短板（实时协作）恰好是个人场景最不需要的，不要提前付这个成本

## 五、换路线的触发条件

| 触发条件 | 换到 |
|---|---|
| 团队 ≥5 人且要实时协作 | 自建 Outline / Docmost，或直接买 Notion / 飞书 |
| 要对外发布、需要搜索与版本 | docs-as-code + 静态站 |
| 已身处大厂飞书 / Confluence 生态 | 用现成的，别迁移（迁移成本高于收益） |
| 只需要「读资料 + 问答」 | NotebookLM / 腾讯 ima，但别当长期知识库 |

## 六、本次讨论暴露的关键风险

**投喂纪律是 llm-wiki 范式的命门。** 成本优势建立在「单源精读」之上；一旦为求快批量灌入，交叉引用质量垮掉，该方案相对 RAG 的唯一优势随之消失。
