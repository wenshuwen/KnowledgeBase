## 三个日常动作

### 1. 投喂（ingest）

**一句话触发**：「归档」「存进知识库」「这条记下来」

可以投喂的形式：
| 形式 | 示例 |
|---|---|
| 口述要点 | 「记一下：压测时 TPS 上不去，先看线程池再怀疑网络」 |
| 文件 | 「把这个日志分析归档一下」+ 文件路径 |
| 链接 | 「这篇文章精读后入库」+ URL |
| 对话回填 | 和我聊完一个结论后说「刚才这段归档」 |
| 自动抓取 | 落到 `raw/inbox/`，你确认后我才编译 |

**投喂时我会做的事**：读出 3–5 条要点跟你确认 → 原料归位 `raw/` → 建页 → 抽取实体页 → 补全库交叉引用 → 更新 `index.md` → 记 `log.md` → Git 提交。

**一次只处理一个源。** 这是质量底线，别催我批量。

### 2. 提问（query）

**一句话触发**：「问问知识库：XXX」「查一下库里的 XXX」

我会读 `index.md` 定位候选页，再读页面给出**带 `[[引用]]` 的回答**。

如果回答本身有价值（横向对比、新发现的知识连接），我会**回填成新页面**，而不是让它烂在聊天记录里。

### 3. 体检（lint）

- 每周自动跑一次，产出报告到 `wiki/00-总览/体检报告-YYYY-MM-DD.md`
- 手动触发：「跑一次体检」
- 重点看报告里的「待你确认」段：矛盾、孤页这两类需要你拍板

检查项见 [`meta/lint-rules.md`](meta/lint-rules.md)。

## 命名约定

- 文件名：**中文**，见名知意 → `并发用户数与TPS的关系.md`
- 标签：**英文 kebab-case** → `#performance-testing`
- 交叉引用：`[[页面名]]`，不带路径

## 红线

- 入库前必须脱敏：项目名、真实域名、业务数据、账号一律替换掉
- 凭据（token / 密码 / 密钥）绝不入库
- `raw/` 里的文件永不修改——要修正认知就改 `wiki/` 页面

## 目录之外的事

**手改页面是可以的。** 改完说一句「同步一下」，我会补 `index.md`、补交叉引用、修失效链接。

**Git**：每次 ingest 后提交，message 格式 `ingest: <页面标题>`。误操作可直接回退。

**想画图谱**：用 Obsidian 把这个目录「打开为库」（Open folder as vault），`[[链接]]` 的关系图立刻可用。目前按纯本地设计，没有绑定任何特定编辑器。
